# Supabase Setup

This project stores **processed, deidentified read models** in Supabase PostgreSQL. Raw child and placement CSVs remain local and are never uploaded.

## Prerequisites

- Supabase project (cloud or local)
- Processed CSVs generated by the ETL:
  ```bash
  python3 -m scripts.etl.main
  ```
- Supabase CLI (recommended): https://supabase.com/docs/guides/cli
- Service role key for loading data locally
- Publishable (anon) key for the deployed Next.js app

## 1. Configure environment variables

Copy `.env.example` to `.env.local` for the app:

```bash
cp .env.example .env.local
```

Set:

```text
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<publishable-anon-key>
```

For local loading only:

```text
SUPABASE_SECRET_KEY=<service-role-secret-key>
```

Never expose the secret key to the browser or commit it to git.

## 2. Link the Supabase project (CLI)

From the repository root:

```bash
supabase login
supabase link --project-ref <project-ref>
```

For a fully local stack:

```bash
supabase start
```

## 3. Apply migrations

Migrations live in `supabase/migrations/`:

| File | Purpose |
| --- | --- |
| `20260722184500_create_read_models.sql` | Tables, constraints, indexes, comments |
| `20260722184501_enable_row_level_security.sql` | RLS policies and anonymous `SELECT` grants |
| `20260722184502_create_filter_options_function.sql` | `get_application_filter_options()` helper |
| `20260724150000_add_provider_outreach_priority_rank.sql` | `outreach_priority_rank` column and performance indexes |

Apply to a linked remote project:

```bash
npx supabase db push
```

Or, if the Supabase CLI is installed globally:

```bash
supabase db push
```

Apply to local Supabase:

```bash
supabase migration up
```

Verify:

```bash
supabase db lint
```

## 4. Load processed CSVs

Load in dependency order because of foreign keys:

1. `dataset_metadata.csv`
2. `system_snapshot.csv`
3. `county_metrics.csv`
4. `county_age_metrics.csv`
5. `provider_metrics.csv`
6. `provider_activity_periods.csv`
7. `monthly_metrics.csv`

### Option A: Python loader (recommended)

The repository includes `scripts/load_to_supabase.py`, a CLI-only loader that reads **only** `data/processed/` files. It is not imported by the Next.js application.

Set environment variables in `.env.local`:

```text
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_SECRET_KEY=<service-role-secret-key>
```

Validate files and counts without writing:

```bash
python3 scripts/load_to_supabase.py --dry-run
```

Load all tables with deterministic, idempotent upserts:

```bash
python3 scripts/load_to_supabase.py
```

Load a single table:

```bash
python3 scripts/load_to_supabase.py --table county_metrics
```

Adjust batch size (default `500`):

```bash
python3 scripts/load_to_supabase.py --batch-size 250
```

The loader:

- Refuses to run without `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SECRET_KEY` (except `--dry-run`)
- Never logs secrets
- Validates row counts against `data/processed/etl_summary.json` before loading
- Verifies database row counts after loading
- Fails if any processed CSV contains `id_child` or other forbidden child-level columns
- Retries transient network failures with bounded exponential backoff

### Option B: Supabase Table Editor / SQL `COPY`

Use the service role in the SQL editor or `psql \copy` from a machine that can reach the database. JSON reason columns (`recruitment_reasons`, `outreach_reasons`) must be valid JSON arrays.

Example `psql` pattern:

```bash
psql "$SUPABASE_DB_URL" -c "TRUNCATE public.provider_activity_periods, public.provider_metrics, public.county_age_metrics, public.county_metrics, public.system_snapshot, public.monthly_metrics, public.dataset_metadata CASCADE;"

psql "$SUPABASE_DB_URL" -c "\copy public.dataset_metadata FROM 'data/processed/dataset_metadata.csv' CSV HEADER"
psql "$SUPABASE_DB_URL" -c "\copy public.system_snapshot FROM 'data/processed/system_snapshot.csv' CSV HEADER"
psql "$SUPABASE_DB_URL" -c "\copy public.county_metrics FROM 'data/processed/county_metrics.csv' CSV HEADER"
psql "$SUPABASE_DB_URL" -c "\copy public.county_age_metrics FROM 'data/processed/county_age_metrics.csv' CSV HEADER"
psql "$SUPABASE_DB_URL" -c "\copy public.provider_metrics FROM 'data/processed/provider_metrics.csv' CSV HEADER"
psql "$SUPABASE_DB_URL" -c "\copy public.provider_activity_periods FROM 'data/processed/provider_activity_periods.csv' CSV HEADER"
psql "$SUPABASE_DB_URL" -c "\copy public.monthly_metrics FROM 'data/processed/monthly_metrics.csv' CSV HEADER"
```

If `recruitment_reasons` / `outreach_reasons` fail type coercion, cast during load or preprocess CSV strings into JSON arrays before import.

## 5. Validate row-level security

Confirm anonymous read access works and writes do not:

```sql
-- As anon (publishable key)
select count(*) from public.county_metrics;
select public.get_application_filter_options();

-- These must fail for anon
insert into public.county_metrics (county) values ('Test');
update public.provider_metrics set outreach_priority = 'High' where provider_id = 500001;
delete from public.system_snapshot where reporting_date = '2026-07-01';
```

Expected:

- `SELECT` succeeds on all seven read-model tables and the filter-options function
- `INSERT`, `UPDATE`, and `DELETE` are denied for `anon`

## 6. Application query notes

- The deployed app uses only the publishable key.
- Server Components should query read models directly; do not expose raw child tables.
- `get_application_filter_options(reporting_date)` returns counties, recruitment priorities, outreach priorities, and age groups for the active snapshot.
- Provider metrics are keyed by `(provider_id, reporting_date)`; the assessment load assumes one active reporting date at a time.

## 7. Refreshing a dataset

1. Re-run the ETL locally.
2. Truncate read-model tables in reverse dependency order (or `CASCADE` from `dataset_metadata`).
3. Reload processed CSVs with `python3 scripts/load_to_supabase.py` or the SQL pattern below.
4. Confirm `dataset_metadata.source_hash` matches `data/processed/etl_summary.json`.

## Security summary

| Role | Access |
| --- | --- |
| `anon` | `SELECT` on read models; `EXECUTE` on `get_application_filter_options` |
| `anon` | No `INSERT` / `UPDATE` / `DELETE` |
| Service role / secret key | Full access for local loading only |

Raw child identifiers and child-level placement episodes are intentionally absent from the database schema.
